About

MPC Sound Lab is an independent digital research studio exploring the intersection of mathematics, physics, sound, music technology, and accessibility. Built with vanilla JavaScript, Web Audio API, and Canvas 2D. No frameworks, no build step, no dependencies.

Founded2024 Version2.0 LicenseMIT
§ 01 The Studio

MPC Sound Lab began as a question: can a web browser serve as a complete scientific instrument for sound analysis? Not a simplified demo, not a toy — a real tool with custom FFT, real-time visualization, and honest measurements.

The answer turned out to be yes, with caveats. The Web Audio API provides sample-accurate access to microphone data. Canvas 2D can render three visualizations at 60fps. A custom radix-2 FFT implementation gives us control over windowing that the built-in AnalyserNode cannot provide.

The caveats are important: browser dBFS is not calibrated to dB SPL. Bin spacing is not the same as frequency resolution. Visual translation is not hearing. Documenting these limitations honestly is a core principle of this studio.

§ 02 Technology
Stack

Vanilla JavaScript — ES6 modules, zero frameworks, zero build step. The entire application loads directly from HTML files.

Web Audio API — AudioContext, AnalyserNode, OscillatorNode, GainNode. All audio processing uses browser-native APIs.

Canvas 2D — Waveform, FFT spectrum, spectrogram, and generative visuals all use the 2D canvas context. No WebGL.

CSS Custom Properties — A token-based design system with no preprocessor.

Custom Implementations

Radix-2 FFT — Because AnalyserNode uses a Blackman window internally and cannot be changed, a custom FFT implementation was needed for the window function explorer.

Autocorrelation pitch detection — Normalized autocorrelation with confidence scoring, running at ~10 Hz.

Energy-based beat detection — Spectral flux with adaptive threshold and median-based BPM estimation.

Harmonic analyzer — Peak detection with integer-multiple validation and reliability scoring.

§ 03 Principles

Local first. All processing happens in the browser. No audio is recorded, transmitted, or stored. The microphone input never leaves your device.

Open and transparent. The code is open source. Every measurement is explained. Every limitation is documented.

Accessible by design. Keyboard navigation, focus-visible outlines, prefers-reduced-motion support, and ARIA labels throughout. The Accessibility module extends this commitment to sound-to-visual translation.

Educational, not just functional. Every tool includes mathematical foundations, physical explanations, and guided experiments. The goal is understanding, not just measurement.
